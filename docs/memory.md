# 会话记忆（移植自 dsh-persona-memory）

## 来源

照抄 [dsh-persona-memory](https://www.npmjs.com/package/dsh-persona-memory) v0.2.4 的机制与文件格式
（该插件与 [pi-hermes-memory](https://github.com/chandra447/pi-hermes-memory) 字节兼容）。
用户明确要求"直接照抄"，所以能照搬的都照搬了，只改了运行环境相关部分。

## 照搬了什么

| 机制 | 上游实现 | 本项目 |
|---|---|---|
| 文件格式 | `MEMORY.md` / `USER.md`，条目 + `<!-- created=..., last=... -->` + `§` 分隔 | 完全一致 |
| 注入 | 包装成 `<memory-context>`，声明"不是用户新说的话" | 完全一致（中文版） |
| 自动学习 | 每 10 轮用会话自己的模型提取事实，每行一条 | 完全一致 |
| 合并护栏 | 只有**严格更小 + 可解析 + 过安检**才替换 | 完全一致 |
| 内容安检 | 凭据、不可见字符、提示注入 | 保留三类，规则表精简 |
| 用户操作 | 无 | 无 |

## 唯一的差异：作用域

上游是**跨会话全局记忆**（一个 MEMORY.md 服务所有会话）。
本项目改成**按会话**（`dsecho-memory:{sessionId}:memory`），因为：

- 本 App 一个会话就是一段角色扮演，不同角色的人设不能混
- 全局记忆会出现"A 角色聊天里的小林，跑到 B 角色对话里自我介绍"

格式不变，只是存储键带上了会话 id。

## 存储位置

浏览器 localStorage（WebView 里没有文件系统），但**存的是同一份文件内容字符串**，
复制出来就是一份合法的 `MEMORY.md`。

## 流程

```
每轮对话结束 → 轮数 +1
  → 到第 10 轮？ → 把最近 40 条消息 + 现有记忆发给模型
  → 模型输出若干行事实 → 安检 → 写入 MEMORY（相同文本只刷新 last 日期）
  → 若超 5000 字符 → 合并压缩（护栏不通过就保留原样）
```

## 验证

### 单测（`tests/memory.test.ts`，16 条）

格式编解码往返、legacy 条目兼容、模型输出去格式化（剥掉编号/围栏）、
合并护栏四条（更短才替换、不许变胖、解析不出拒绝、含凭据拒绝）、安检五类。

### 端到端（`/.verify/memory/e2e.py`）

真实浏览器 + 拦截请求（不花钱）：

| 断言 | 结果 |
|---|---|
| 第 10 轮触发学习 | 是（1 次学习请求） |
| 学到的 3 条事实写入记忆 | 是，格式与上游一致 |
| 第一次请求带记忆 | 否（当时还没记忆） |
| 第二次请求带记忆 | **是** |
| 注入内容含事实原文 | 是（"旧书店店主"出现在 system 里） |

## 已知限制

- 没有界面入口：用户看不到记忆内容（按"用户什么都不用做"的要求）。
  如果以后要加，建议只读展示 + 清空按钮，不要做成编辑器。
- 合并只按字符数触发（5000），没有按 token 精确控制。
- 学习固定每 10 轮，没有根据会话长度动态调整。
- 失败只记日志，不会提示用户（记忆是增强项，坏消息不值得打断对话）。
