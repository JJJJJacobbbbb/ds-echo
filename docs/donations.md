# 打赏名单怎么维护

## 最短路径（不用发版）

1. 打开 <https://github.com/JJJJJacobbbbb/ds-echo/blob/main/donations.json>
2. 点右上角铅笔图标（Edit）
3. 加一条记录：

```json
{ "name": "小林", "amount": 6.66, "message": "很好用，谢谢", "date": "2026-11-18" }
```

4. 页面底部 **Commit changes**

**生效时间**：用户下次打赏弹窗打开时拉取；jsDelivr 有 CDN 缓存，通常几分钟到几小时。
想立刻生效可以在记录里改一下 `date`，或用 raw 源（App 会在 jsDelivr 失败时自动回落）。

## 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `amount` | 是 | 数字，排序按它从大到小；显示时自动加 `¥` 和两位小数 |
| `name` | 否 | 留空或写"匿名"都显示成「匿名」 |
| `message` | 否 | 一句话，太长会被省略号截断 |
| `date` | 否 | 只用于区分同名同额条目，不显示 |

## 规矩（建议自己守住）

- **先问再写**：对方是花钱支持你，名字和留言公开前最好确认一句
- **不编造**：没有的记录不要写，这比空名单更糟
- **金额别改**：人家给多少就是多少

## 为什么名单要手动维护

本 App 没有后端、也不收集用户数据，所以拿不到"谁付了钱"这种信息
（微信/支付宝的个人收款也没有回调通知）。只能你看到账后手动记一笔。

## 兜底

App 内置了一份名单（`src/data/donations.json`），远端拉不到时显示它。
所以即使 GitHub 完全打不开，弹窗也不会空着。

## 想彻底自动化的话

需要接一个能收到支付回调的渠道（如爱发电、有赞等），但它们都有抽成，
而且要把订单数据同步到 App —— 对一个个人项目来说不划算。
